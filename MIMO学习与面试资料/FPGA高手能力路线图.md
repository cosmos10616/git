# FPGA高手能力路线图

## 一、什么才算真正的FPGA能力

真正的FPGA高手，不只是能够写出RTL，而是能够：

> 把算法或需求转化成可综合、时序收敛、资源合理、验证充分、上板稳定的硬件系统，并在出现问题时快速找到第一个错误边界。

完整能力可以分成12个方向：

```text
数字电路基础
→ RTL与微架构
→ 时序设计和STA
→ 验证
→ CDC与复位
→ FIFO/RAM和数据流
→ 定点DSP
→ 吞吐与资源设计
→ FPGA完整工具流程
→ 协议与高速接口
→ 上板调试
→ 自动化、规范和领域算法
```

## 二、数字电路基础

必须真正理解：

- 组合逻辑和时序逻辑；
- 建立时间和保持时间；
- 亚稳态；
- 阻塞赋值和非阻塞赋值；
- 锁存器为什么产生；
- 状态机、计数器和流水线；
- 同步复位和异步复位；
- 时钟使能和门控时钟；
- 有符号数、补码和位宽扩展。

看到RTL时，脑中应该能大致画出：

```text
寄存器
MUX
比较器
计数器
RAM/FIFO
乘法器和加法器
```

而不是只把Verilog当成顺序执行的软件程序。

### 在F0工程中怎么练

- 阅读`PULSE_TO_STROBE`时画出状态、寄存器和逐拍波形；
- 阅读FIFO控制时区分组合条件和寄存器输出；
- 检查所有计数器的起点、终点、回绕和`N=0/1`边界；
- 检查切片、拼接和`signed`传播是否符合预期。

### 掌握标准

不运行仿真，也能根据RTL手工写出5～10拍的关键信号波形。

## 三、时序设计和STA

这是从“会写代码”走向“会做工程”的关键。

需要掌握：

- 时钟约束；
- 输入输出延迟；
- setup/hold违例；
- WNS和TNS；
- critical path；
- false path和multicycle path；
- 时钟偏斜和抖动；
- 为什么增加流水级能改善时序；
- 高扇出控制信号怎样处理。

例如32项复数点积不适合在一个周期内完成，通常要组织成：

```text
复数乘法
→ 分级加法树或流水累加
→ 截位、舍入和饱和
```

不仅要关心计算结果正确，还要关心它能否在目标时钟频率下运行。

### 在F0工程中怎么练

- 对`Channel_Equalizer_Dot_Product`建立每一级延迟表；
- 综合后找到最慢路径，判断它属于乘法、加法、RAM还是高扇出控制；
- 尝试增加一级寄存器，再比较WNS、FF数量和总延迟；
- 检查所有IP核声明的延迟是否与valid延迟链一致。

### 掌握标准

能够解释一个时序违例从哪里来，并提出流水化、复制寄存器、调整结构或正确约束等解决方法。

## 四、验证能力

RTL写完通常只完成了一半。需要掌握：

- 编写自检Testbench；
- 构造正常、边界和异常输入；
- 使用软件参考模型；
- 自动比较预期结果；
- 检查`valid/ready`；
- 使用SystemVerilog Assertion；
- 功能覆盖率；
- 定位第一个错误周期；
- 必要时进行门级或时序仿真。

信道估计模块可以按下面的方法验证：

```text
软件计算预期H
→ RTL输入已知导频和接收导频
→ 自动比较RTL输出
→ 同时检查数值、顺序和valid
```

不要只打开波形观察“看起来差不多”。

### 推荐Testbench结构

```text
激励生成器
→ DUT
→ 输出监视器
→ 参考模型/期望结果队列
→ Scoreboard自动比较
→ Assertion检查协议
```

### 掌握标准

Testbench能够自动给出PASS/FAIL，并指出第几个数据、哪一个字段、哪一拍开始不一致。

## 五、CDC、复位和跨时钟设计

真实工程通常存在多个时钟域，需要掌握：

- 单bit两级同步；
- 脉冲跨时钟；
- 握手同步；
- 异步FIFO；
- Gray码指针；
- 多bit数据为什么不能逐bit同步；
- reset deassertion同步；
- CDC和RDC检查。

F0工程中的典型时钟域包括：

```text
clk_baseband
clk_udp
高速片间链路时钟
射频采样相关时钟
```

### 在F0工程中怎么练

- 跟踪`Bit_to_UDP`的数据怎样从基带时钟域进入UDP时钟域；
- 区分数据跨域、脉冲跨域和状态跨域；
- 自己实现一个双时钟异步FIFO；
- 对复位释放进行同步处理，并检查不同域是否可能提前工作。

### 掌握标准

能够根据数据速率和控制类型选择两级同步、Toggle、握手或异步FIFO，而不是所有信号都直接打两拍。

## 六、FIFO、RAM和数据流设计

大型FPGA工程的主体往往是缓存和搬运数据。需要理解：

- 同步FIFO和异步FIFO；
- `full`、`empty`、`almost_full`；
- FWFT和普通FIFO；
- RAM读延迟；
- 单口、简单双口、真正双口RAM；
- Ping-Pong Buffer；
- 突发数据的生产和消费速率；
- FIFO深度怎样估算；
- 背压和流控；
- 数据重排地址生成。

F0工程的数据顺序会经历：

```text
Layer顺序
→ RB顺序
→ 天线顺序
→ 子载波顺序
→ 再恢复Layer顺序
```

### 在F0工程中怎么练

- 单测`RX_Reordering`，给每个数据写入可识别的Layer/RB/子载波编号；
- 检查不同写地址和读地址怎样完成转置式重排；
- 单测`Read_and_Unpack`和两个Exchange模块；
- 根据最坏突发长度和消费间隙估算FIFO最小深度。

### 掌握标准

能够在设计前画出生产者/消费者速率图，并证明FIFO不会溢出或读空。

## 七、定点算法和DSP实现

通信、雷达和图像类FPGA尤其需要定点能力。需要掌握：

- 浮点转定点；
- Q格式；
- 复数乘法；
- 乘法后的位宽增长；
- 累加保护位；
- 截断和四舍五入；
- 饱和与回绕；
- 量化误差、SNR和EVM；
- DSP Slice映射；
- CORDIC、FFT和FIR的硬件实现。

接收均衡器的运算为：

\[
\hat{x}_l=\sum_{a=0}^{31}W_{l,a}y_a
\]

除了公式，还必须回答：

```text
输入是什么定点格式？
乘积多宽？
32项累加需要增加多少保护位？
最终截取哪些位？
采用截断还是四舍五入？
溢出时饱和还是回绕？
```

### 在F0工程中怎么练

- 为`Channel_Estimation_WDP4`建立浮点和定点两份参考模型；
- 为复数乘法列出每个中间结果的Q格式；
- 对`Channel_Equalizer_WDP4`测试最大正负输入和32项同向累加；
- 比较不同小数位、舍入方式对均衡误差的影响。

### 掌握标准

能够为一条完整DSP流水线画出逐级位宽表，并用测试证明不会发生未预期的回绕溢出。

## 八、架构和吞吐率设计

拿到算法后应该先计算：

- 每秒需要处理多少数据；
- 每拍需要处理几个样点；
- 是否能够分时复用乘法器；
- 需要多少并行通路；
- FIFO需要多深；
- 延迟和吞吐率是否满足要求；
- 资源和性能如何折中。

F0工程每拍处理4个子载波，是因为：

```text
4个复数 × 32 bit = 128-bit接口
```

一个RB有12个子载波，因此正好拆成3个四位置小块。这是从吞吐和接口宽度反推硬件并行度的例子。

### 掌握标准

在写RTL前，能够给出吞吐率、并行度、延迟、DSP数量和缓存量的初步预算。

## 九、FPGA完整工具流程

完整流程包括：

```text
RTL仿真
→ 综合
→ 查看资源报告
→ 布局布线
→ 时序分析
→ 生成bit文件
→ ILA上板调试
```

需要看懂：

- LUT、FF、BRAM和DSP使用率；
- 综合警告；
- latch、未驱动信号和多驱动；
- 时序报告和时钟报告；
- RAM和DSP是否按预期推断；
- 为什么仿真正确但上板错误。

### 掌握标准

能够从干净工程开始重复构建bit文件，并解释关键警告、资源瓶颈和最慢路径。

## 十、常用协议和接口

建议掌握：

- AXI4、AXI4-Lite和AXI-Stream；
- `ready/valid`握手；
- UART、SPI和I²C；
- Ethernet/UDP；
- DDR接口基础；
- PCIe基础；
- JESD204B/C或高速ADC/DAC接口；
- Aurora或其他高速串行链路。

不需要一开始全部精通，但至少要完整掌握：

```text
一套片内流接口
+
一套跨时钟接口
+
一套高速板级接口
```

结合当前项目，可以优先学习AXI-Stream、UDP和Aurora数据链路。

## 十一、上板调试和硬件知识

需要掌握：

- ILA和VIO；
- 选择真正有意义的探针；
- 用计数器统计丢包、CRC和FIFO满空；
- 检查时钟和复位；
- PLL/MMCM；
- 引脚、电平标准和差分信号；
- 阅读原理图；
- 使用示波器或逻辑分析仪；
- 区分RTL问题、时序问题和板级问题。

推荐调试方法：

```text
观察现象
→ 提出可以被验证的假设
→ 选择能够证明或否定假设的最少探针
→ 找到第一个错误边界
→ 修复后重新验证原问题和相关边界
```

不要只是不断增加ILA探针。

## 十二、脚本、版本管理和工程规范

建议掌握：

- Git分支、提交、回退和代码评审；
- Tcl自动建立Vivado工程；
- Python/Matlab生成测试数据和参考结果；
- 自动运行仿真；
- 自动比较输出；
- 参数化RTL；
- 清楚的接口和时序文档；
- lint和代码规范。

目标是让工程能够被重复构建、重复测试，而不是依赖某一台电脑当前的Vivado状态。

### 每个模块建议保留的文件

```text
rtl/        被测RTL或独立重写版本
tb/         自检Testbench
vectors/    输入和参考输出
scripts/    仿真与结果比较脚本
docs/       接口卡片、位宽表和验证结论
```

## 十三、深入一个应用领域

FPGA是实现工具，最好长期深入一个领域：

- 通信：OFDM、MIMO、同步、信道估计和信道编码；
- 图像：滤波、卷积和视频协议；
- AI：矩阵乘法、量化和存储调度；
- 存储：DDR控制、ECC和缓存；
- 网络：包解析、交换和流量调度；
- 雷达：FFT、CFAR和波束形成。

当前最适合建立的能力组合是：

```text
MIMO/OFDM算法
+ 定点复数流水线
+ 高速数据重排和FIFO
+ 自检验证
+ 时序分析
```

## 十四、结合F0工程的学习顺序

### 阶段1：从“看懂”升级到“能验证”

1. `PULSE_TO_STROBE`：计数器、边界和接口协议。
2. `Pilot_Generation_WDP4`：确定参考导频。
3. `Channel_Estimation_WDP4`：复数乘法、定点和自检Testbench。
4. `Channel_Equalizer_WDP4`：32项复数累加和流水控制。
5. `Turbo_Encoder_Top`：状态机、码块和固定向量验证。

### 阶段2：从“能验证”升级到“能独立设计”

1. 不看源码重新写一个简化版信道估计器；
2. 独立设计参数化复数点积模块；
3. 独立设计同步FIFO和异步FIFO；
4. 独立实现RAM矩阵转置/重排；
5. 为每个模块编写自动检查Testbench。

### 阶段3：从“功能正确”升级到“工程可用”

1. 综合并检查资源推断；
2. 建立时钟和I/O约束；
3. 查看WNS/TNS和关键路径；
4. 对关键路径流水化；
5. 检查CDC和复位释放；
6. 生成bit文件并使用ILA验证。

### 阶段4：从“单模块”升级到“完整系统”

```text
导频生成
→ 信道估计
→ MMSE权矩阵
→ 均衡
→ 软解调
→ Turbo译码
→ CRC
```

逐级建立参考结果，最后完成可控信道下的接收闭环。

## 十五、判断自己是否真正掌握一个模块

对每个模块回答以下问题：

```text
1. 我能用一句话解释它为什么存在吗？
2. 我能说明每一拍输入和输出代表什么吗？
3. 我能不看源码重新设计一个简化版本吗？
4. 我能写自检Testbench证明它正确吗？
5. 我能说明定点位宽、延迟和吞吐率吗？
6. 我能看综合和时序报告判断它能否上板吗？
7. 出错时我能找到第一个错误边界吗？
```

前两项只能说明“看懂了”，前四项说明“掌握了”，全部做到才接近工程上的熟练。

## 十六、近期最重要的四项任务

1. 为信道估计、Turbo编码和均衡器编写自检Testbench。
2. 为每一级运算建立定点格式、位宽增长、截位和饱和表。
3. 学会查看综合资源和时序报告，并实际优化一个关键路径。
4. 独立实现简化版信道估计、复数点积和FIFO重排，而不只是阅读原工程。
