# FPGA 模块解读 Skill

解读本工程任何一个 FPGA 模块时，严格遵守以下流程。

## 核心原则

**从 RTL 代码出发，不要从教科书概述出发。** 每一个结论都要能追溯到具体的文件+行号。

---

## 第一步：定位模块

先回答：
- 模块在哪个文件、哪些行
- 上游：谁给它数据
- 下游：它给谁数据
- 时钟：在哪个时钟域

```
模块名.v (第X-Y行)
  上游: XXX
  下游: YYY
  时钟: clk_xxx
```

---

## 第二步：画子模块调用链（必须）

用 Grep 找出模块内所有实例化，画出层级树，标注文件内行号：

```
父模块.v
  ├── 子模块1 (第X行) — 做什么
  │     ├── 孙模块A — 做什么
  │     └── 孙模块B — 做什么
  ├── 子模块2 (第Y行) — 做什么
  └── 子模块3 (第Z行) — Xilinx IP核 / EDIF网表
```

---

## 第三步：知识点逐条展开

每个子模块涉及的知识点要展开，不能一笔带过：

### 算法原理
- 数学公式 → 对应 RTL 哪几行 → 为什么用这种实现方式
- 例：QPP 交织器 Π(i) = (f1·i + f2·i²) mod K → 迭代加法代替乘法器 → RTL 中用 3 个 Calculation_Core 级联

### 硬件实现技巧
- 分时复用、流水线打拍、迭代代替乘法、查表代替计算、ping-pong 缓冲
- 每个技巧要说清楚：不用会怎样、用了省了什么

### 协议背景
- 对应 LTE/5G 协议的具体章节号和公式
- 代码中的值是怎么从协议公式算出来的

### 关键参数的计算过程
- 每个延迟值为什么是这个数（不是"大概够用"）
- 每个常数的物理含义（如 ENCODE_SAFE_VALUE=20000）

---

## 第四步：贴关键代码行

引用最核心的几行 RTL，标注文件+行号：

```verilog
// 文件名.v 第X行 — 这行做了什么
关键代码
```

"关键"的定义：状态转移条件、数据选择/切换逻辑、延迟匹配、复位处理。

---

## 第五步：回答"这个在哪实现的"

格式必须是层级树：
```
父模块.v 第X-Y行实例化了这三个子模块：
  ├── 子模块A — 负责XXX
  ├── 子模块B — 负责YYY
  └── 子模块C — 负责ZZZ (Xilinx IP核)
```

---

## 第六步：纠正错误必须精确到行

如果用户指出某个推导有错：
1. 先说清错在哪一行、哪个变量算错了
2. 再用正确值逐拍追踪一遍
3. 最后给出代数证明（如果是数学问题）

---

## 第七步：写入笔记文件

所有交流的技术内容，整理后写入项目根目录的 `mimo深度学习交流.md`。

格式要求：
- 用 `## N. 模块名（第X级）— 日期 精读` 作为章节标题
- 包含完整的子模块调用链、知识点展开、关键代码
- 保留讨论/Q&A 部分
- 每次写完检查文件大小，超过 3000 行时主动询问是否整理归档

---

## 禁止的做法

- ❌ 不贴代码行号就讲原理
- ❌ 用"数学保证""协议规定"搪塞而不追踪到代码
- ❌ 不画子模块层级树就展开讲
- ❌ 知识点一句话带过（如"这里用了流水线"但不解释几级、为什么）
- ❌ 修改文件前不确认是哪个文件
- ❌ 只讲课本原理不讲硬件怎么实现的
