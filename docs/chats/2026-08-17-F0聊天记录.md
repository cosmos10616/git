### 2. `PULSE_TO_STROBE_U16_delay1` 重写

- 原模块作用：收到单周期 `start_pulse` 后，把它扩展为连续 `N` 拍的 `strobe`，同时输出 `index=0,1,...,N-1`。
- 原模块启动时锁存 `N`，忙状态下忽略新的 `start_pulse`，结束后需要回到等待状态才能接受下一次启动。
- 重写过程中核实了几个典型错误：
  - `index` 从1开始会丢失第0项。
  - 用 `N >= index` 或 `N > index` 判断继续会产生额外输出拍。
  - 正确主判断可写为 `index_reg == N_module - 1'b1`，即当前索引到达最后一项时结束。
  - `N` 必须在启动时锁存，不能在忙状态下一直直接读取外部 `N`。
  - `N=0` 时 `N_module-1` 会无符号下溢；若协议允许0，需要单独处理。
  - 建议给状态机增加 `default`，用于非法状态恢复。
- 对 `N=3`，正确输出为：`strobe` 连续3拍有效，`index` 依次为0、1、2。

### 3. Verilog/SystemVerilog Testbench

- 双DUT对比方法：把完全相同的 `clk/rst_n/start_pulse/N` 同时送给原模块和重写模块，逐拍比较 `strobe` 和 `index`。
- `error_count=0` 表示当前测试集合内两者输出一致；大于0表示至少有一拍不一致。与旧模块等价并不自动证明旧模块规格完全正确，边界条件仍需按规格单独验证。
- Testbench输入用 `reg` 驱动，被测模块输出用 `wire` 接收；Testbench本身没有端口。
- 在时钟下降沿改变输入，使数据在下一上升沿到来前稳定，避免Testbench与DUT在同一上升沿发生仿真竞争。
- 在上升沿后等待 `#1` 再检查输出，是为了让非阻塞赋值完成；该延迟只用于仿真，不会综合成硬件。
- `!==`/`===`会把 `X/Z` 也纳入比较，适合自检Testbench。
- `$display`、`$finish` 等以 `$` 开头的是仿真器提供的系统任务，不会综合为FPGA硬件。
- Vivado应选择 `Run Behavioral Simulation`。时间框中的 `10 us` 是一次 `Run For` 的推进时间；`Run All` 会一直运行到 `$finish`、断点或没有后续事件。
- 若时钟由 `forever` 产生而测试流程没有执行到 `$finish`，`Run All` 会持续运行。时钟生成和测试激励应放在两个并行的 `initial` 块中，不能把 `$finish` 写在同一块的 `forever` 后面。
- 修改代码后应保存并 `Relaunch Simulation`，确保Vivado重新编译，而不是继续运行旧的仿真快照。

### 4. `MUL_12` 常数乘法器IP

- IP类型为 Constant Coefficient Multiplier，固定计算 `P=A×12`，因此运行时只输入 `A`，不需要外部 `B`。
- `A` 为9位无符号数，范围0～511。
- 自定义输出为 `P[11:0]`，保留完整乘积的低12位。由于 `511×12=6132` 需要13位，当前配置会截掉bit12，相当于输出 `(A×12) mod 4096`。
- 最大不溢出的输入为341：`341×12=4092`；`342×12=4104` 时低12位结果为8；`511×12=6132` 时低12位为2036。
- 若希望覆盖全部9位输入而不溢出，应输出13位 `P[12:0]`。
- Pipeline Stages配置为2：增加运算延迟以改善时钟性能；流水线填满后仍可做到每拍输入一个数、每拍输出一个数，延迟与吞吐率不是同一个概念。
- IP未启用CE和SCLR，因此流水线每拍推进，且没有内部复位端口；仿真初期输出可能为X，应先灌入已知输入并用有效信号标记结果。
- 已为IP编写测试封装，通过两级 `valid_pipe` 为没有valid端口的IP补充 `in_valid/out_valid` 对齐；Testbench用task逐个发送测试值、等待 `out_valid`、截取软件参考结果低12位并自动比较。
