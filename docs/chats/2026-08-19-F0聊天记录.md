# 2026-08-19 F0聊天记录

## 今日问题

用户询问：整个MIMO工程发射端和接收端的FFT/IFFT分别位于哪一部分、哪个模块，以及从链路开头到结尾数据依次经过了哪些处理。

## 已核实结论

### 1. 发射端OFDM IFFT不在TX_RRH_Chain

当前主层级实际为：

```text
TX_BIT_Processor
→ Combine_Control_and_Data
→ DC_Insertion（3600有效位置+495保护位置=4095，再插1个DC得到4096）
→ WFRFT_TX
→ Normalization_FFT_wo_shift
→ FFT_4096
```

`WFRFT_TX` 使用一套4096点FFT以及RAM正序/反序读取构造 `X0=x`、`X1=F·x`、`X2=F²·x`、`X3=F³·x`。利用归一化DFT的 `F⁴=I`，`X3=F⁻¹x` 是IFFT等效分量（实际还受IP缩放和定点截位影响）。当前生效的选择为：

- `alpha=10`：选择 `X1`，即FFT分量；
- `alpha=30`：选择 `X3`，即IFFT等效分量；
- 其他值：选择 `X0`，即直通。

`WFRFT_Alpha_Indicate` 对指定RS符号产生 `using_ifft`，父模块对齐后把 `alpha` 强制为30。

`TX_RRH_Chain.v` 已明确把原IFFT改为直通，当前只执行 `TX_Unpack_Data → 拆分两天线I/Q → CP_Insertion → PSS时域选择`。所以旧图中“TX RRH做IFFT”的说法已经纠正。独立文件 `Normalization_IFFT.v` 存在，但未进入当前MIMO主层级。

### 2. 接收端OFDM FFT位于RX_RRH_Chain

主数据路径为：

```text
8天线时域I/Q
→ Sync_Top产生First_sample_index和precise_cfo
→ Align_output_with_CFO_compensation完成帧对齐与频偏补偿
→ CP_Removal丢掉320/288点CP
→ 每根天线保留4096点时域正文
→ FFT_All_Remain
→ FFT_4096
→ 每根天线4096个频域点
```

每个 `RX_RRH_Chain` 处理两根天线并例化两套 `FFT_All_Remain`；每片FPGA有四条Chain，因此本地8根天线各有一套4096点FFT。FFT后经 `DC_Position_Change` 移动DC位置并缩放，再由 `RX_Pack_Data` 打包为64-bit流。

### 3. FFT之后的MIMO和BIT链

```text
RX_RRH_FIFO_Exchange汇聚同一频率块的32天线
→ RX_MIMO_Processor资源分离、信道估计、MMSE权重和均衡
→ 32天线恢复12 Layer
→ RX_MIMO_Data_Processing分回每板3 Layer
→ RX_Reordering恢复每Layer连续4096点
→ DC_Recover恢复DC位置
→ WFRFT_RX完成WFRFT逆配对
→ Substract_Subcarrier_Top从4096点取出3600有效位置
→ 资源解映射、软解调、解扰、逆速率匹配、Turbo译码、CRC和UDP
```

`WFRFT_RX` 内部也有一套 `FFT_4096`，但这不是第二次OFDM解调FFT，而是结合前级RRH FFT恢复发射端WFRFT：

- `alpha=30`：TX选择 `F³`，RRH FFT再乘 `F` 已得到 `F⁴=I`，所以RX WFRFT选择 `X0`直通；
- `alpha=10`：RX WFRFT选择 `X2`；
- 其他值：RX WFRFT选择 `X3`。

### 4. 发射端从开头到结尾

```text
MAC/UDP bit
→ CRC/Turbo/速率匹配/加扰
→ QAM频域复数符号
→ PDCCH/PDSCH/RS资源映射
→ 4096点频域结构
→ WFRFT_TX（alpha=30时为IFFT等效输出）
→ TX_BIT_FIFO_Exchange汇聚12 Layer
→ TX_MIMO_Processor形成32发射天线
→ TX_RRH_FIFO_Exchange按天线分板
→ TX_RRH_Chain直通、加CP、PSS选择
→ Over_Sample_Group做FIFO速率调整和FIR插值
→ DAC/RF
```
