## 已核实的接收端整体结论

### 1. 接收端总数据流

```text
每片FPGA的8根接收天线时域IQ
→ RX_RRH_Processor：同步、频偏补偿、去CP、4096点FFT
→ RX_RRH_FIFO_Exchange：第一次跨板交换，同一RB汇齐32根天线
→ RX_MIMO_Processor：H(32×12)、MMSE W(12×32)、x_hat=Wy
→ RX_MIMO_Data_Processing：12条Layer按每板3条再次跨板分发
→ RX_BIT_Processor_Top：资源解映射、软解调、软解扰、Turbo译码、CRC、UDP
```

### 2. 关键数据量

- 一个RB有12个子载波，RTL按4个连续频域位置并行处理，因此一个RB分为3个四位置小块。
- 32根天线的一个RB共有 `32×12÷2=192` 个64-bit字。
- 每片FPGA在BIT部分负责3条Layer，一个普通RB需要 `3×12÷2=18` 个64-bit字，特殊四位置尾块需要6个。
- MIMO信道矩阵为 `H:32×12`，MMSE均衡矩阵为 `W:12×32`，均衡关系为 `x_hat=Wy`。
- BIT重排把按RB/小块/Layer交错的数据恢复为三段连续4096点，再拆成三路Layer处理。

## 降采样讨论

- 单独进行4倍降采样会使新采样率变成原来的1/4，原频谱的4个周期副本在新奈奎斯特区间内叠加；超出新奈奎斯特频率的分量会折回形成混叠。
- 抗混叠FIR必须位于降采样之前，先滤除降采样后会折叠进有效带宽的高频分量，再每4点取1点。
- `Coarse_Timing_Estimation` 中的32倍抽取服务于低复杂度PSS粗搜索，不是业务数据降采样链；这里没有单独的抗混叠低通，是检测复杂度与性能之间的折中。

## Coarse_Timing_Estimation

### 输入输出

- 输入：参考天线4的C1.15时域IQ、`data_in_valid`、`enable_new_trigger`。
- 输出：单拍 `PSS_detected_trigger` 和环形RAM起点地址 `First_sample_index[14:0]`。
- `enable_new_trigger`只封锁最终触发，不停止前面的抽取和相关计算。

### 处理步骤

```text
天线4时域IQ
→ 每32个有效样本取1个
→ 128点本地PSS复相关
→ 相关实部、虚部模平方
→ PSS_peak_search
→ PSS_detected_trigger
→ 粗位置×32并固定回退、模20480
→ First_sample_index
```

- 5-bit计数器仅在 `data_in_valid=1` 时递增，`counter==0` 时产生 `valid_dec32`，实际为32倍抽取；旧注释中的16倍说法与RTL不符。
- 4096点PSS经过32倍抽取仍保留约128个点，因此不会跳过整段PSS；但存在32种抽取相位，只保留约32个原采样的粗定时分辨率，并可能损失部分相关峰高度。
- 例：抽取器选择全局 `x0,x32,x64...`，若PSS从 `x13` 开始，则落入PSS的点为 `PSS[19],PSS[51],PSS[83]...`。它们与本地 `PSS[0],PSS[32],PSS[64]...` 是同一序列的不同抽取起始相位。

## cross_correlation

### 两个FIR为什么输入相同

- 两只FIR都输入 `{Q,I}` 是有意设计，不是重复写错；每只FIR配置两条path，同时处理I和Q。
- `cross_corr_R_part`使用PSS实部系数，`cross_corr_Q_part`使用PSS虚部系数，组合四项 `I·P_R`、`Q·P_R`、`I·P_I`、`Q·P_I` 得到复相关。
- 令 `A=ΣI·P_R`、`B=ΣQ·P_R`、`C=ΣI·P_I`、`D=ΣQ·P_I`，RTL组合为 `corr_real=A+D`、`corr_imag=C-B`。虚部相对标准 `r·p*` 整体反号，但后续只计算平方和，因此不影响峰值；若以后使用相关相位，需要重新核实符号。

### FIR流式计算和valid

- 两只FIR均为128 taps、16-bit Signed输入、16-bit Signed系数、37-bit Full Precision输出。
- FIR按流工作：每接受一个有效新样本，128点历史窗口移动一格并启动当前窗口点积；填满后可做到每个有效输入对应一个相关输出。
- AXI-Stream严格接收条件是 `tvalid && tready`；当前RTL没有使用`tready`，依赖稀疏valid保证IP能够接收，建议仿真增加检查。
- FIR通过 `m_axis_data_tvalid`指出输出有效，模块使用`Q_part_out_valid`代表两只同配置FIR共同有效。

### 相关能量和位宽

```text
C = C_R + jC_I
uncliped_magnitude = clip(C_R)^2 + clip(C_I)^2
magnitude_out = uncliped_magnitude舍入并去掉8个低位
```

- `uncliped_magnitude[47:0]`是当前128点接收窗口与本地PSS的复相关模平方，不是单个IQ采样的普通功率。
- `MUL_I24_I24`配置为24-bit Signed乘24-bit Signed、48-bit全宽输出、4级流水线，能够正确计算负相关分量的平方。
- 乘法IP没有valid或CE，每拍都计算；模块将FIR valid延迟8拍，与“相关组合1拍 + 舍入1拍 + 乘法4拍 + 平方和1拍 + 最终舍入1拍”对齐。
- 当前实现没有通用饱和保护。FIR全精度、乘法全宽以及归一化PSS系数共同限制幅度；若改变输入增益或系数，37-bit加减和两个48-bit平方和仍可能回绕，需要仿真检查。

## PSS_peak_search

### 输入输出与主线

- 输入：40-bit非负相关能量 `magnitude_in`、`magnitude_valid`、`enable_new_trigger`。
- 输出：单拍 `PSS_detected_trigger` 和保持型 `First_sample_index`。
- 它不是保存整帧后寻找全局最大值，而是在线判断一个延迟后的候选点：局部极大、明显高于背景并且允许触发时立即确认PSS。

### 约255点历史队列

`delay_en`用40-bit宽移位寄存器保存有效相关点；只有 `magnitude_valid=1` 时移动。若最新点为 `M[t]`：

```text
newest_value    = M[t]
value_delay_126 = M[t-126]   候选点右邻
center_value    = M[t-127]   当前候选峰
value_delay_128 = M[t-128]   候选点左邻
oldest_value    = M[t-254]
```

局部极大条件：

```text
center_value >= value_delay_126
且 center_value >= value_delay_128
```

因此模块不是提前看未来点，而是等右邻点到达后回头判断历史候选点。

### 滑动能量门限

窗口总能量用：

```text
sum_energy = sum_energy + newest_value - oldest_value
```

在线维护，不需要每次重新累加约255点。最终条件近似为：

```text
center_value × 8 > sum_energy
```

若按约256点窗口理解，相当于候选峰大于局部平均相关能量约32倍。

### 地址换算

- `Mod_N_Indexer`只在新相关结果有效时按0～639循环计数，因为 `20480/32=640`。
- `{data_in_index,5'd0}`等价于粗位置乘32，恢复到原采样地址尺度。
- 当前地址公式可概括为：

```text
First_sample_index
= (data_in_index×32 - 17280 - FFT_advance_timing)
  mod 20480
```

- `FFT_advance_timing=24`；`CONST1=17280`强依赖PSS帧内位置、相关/峰值延迟和RAM结构，旧注释与现参数不完全一致，仍需PSS注入仿真验证。

### 已发现风险

- `sum_energy`、`local_max`、`PSS_detected_r`和`First_sample_index_r`缺少明确复位，RTL仿真可能从X状态开始。
- 时序always块使用阻塞赋值，建议后续核实仿真/综合语义并考虑改为规范的非阻塞写法。
- 局部最大使用`>=`，平台峰可能产生相邻候选；依靠触发禁止逻辑抑制重复触发。
